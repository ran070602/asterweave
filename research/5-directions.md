## D1. 雷线谜图 —— 扫雷 × 数织 ✅ 首选

**一句话概念**：一张网格上同时挂着两种"不完整信息"——每个被探测的格子告诉你**周围有几颗雷**（扫雷），每一行/列还告诉你**雷的连续块长度**（数织）。你要只用逻辑推出全部雷的位置，且**每一关都保证不需要猜**。

**元素A × 元素B**
- 元素A（扫雷）：局部邻域计数 → "一格与它周围 8 格"的约束。
- 元素B（数织）：行列连续块线索 → "整行/整列里雷成段分布"的全局约束。
- **化学反应（已被实测证实，不是设计者的自我感觉）**：`[实测]` 6×6 / 7 雷 / 6 探测格，各 400 次采样：
  | 线索 | 唯一解率 | 无猜可解率 |
  |---|---|---|
  | **只有扫雷计数** | **0.0%** | **0.0%** |
  | **只有数织行列线索** | 14.5% | 13.8% |
  | **两者混合** | **70.2%** | **60.2%** |

  → **任何一半单独都不成立，合起来才收敛**。这就是官方说的"没有新元素，新的是碰撞"的硬证据。50 关生成 **79 次尝试 / 0.10 s**（接受率 63.3%，平均 1.6 次拒绝/关）。

**与 Meowdoku 的区别（要写进设计思路文档第一段 + 第 2 关教学里，T5 建议）**
> Meowdoku = **数独 × 扫雷**，约束类型是"每行/列/宫**不重复**"（唯一性）。本方向用的是"连续块**形状**约束"，玩家做的是**连续段切割 + 邻域排除**，不是"唯一性排除"。
> `[GitHub API]`（2026-10-21）`minesweeper nonogram in:name` = **0** —— 弱信号：只说明没有这样命名的开源克隆，**不等于没人做过，禁止宣称"全球首个"**。

**评分映射**
- 玩法 50%：规则两句话说完，但有真实推理深度，且融合本身经过实测验证 → "巧妙"成立。
- 关卡 30%：⚠️ **修正后的说法（原 v1 的"难度可用数字排序"被 T5 实测推翻）**：可以自动生成 50 关、可以自动标注**可观测参数**（尺寸 / 雷数 / 探测格数 / 线索粗细），但**不能用求解器统计量排序难度**——原因是一个自毁循环：**筛掉"需要猜测"的关卡，就把这些统计量抹平了**（50 关样本里"推导事件数"恒为 30、"唯一解搜索节点"恒为 0、"最长瓶颈链"恒为 1，都只有 1/50 个不同值）。可用的替代指标只有 `首轮推导格数`（17/50 个不同值）与 `推导 profile`（30/50）。
  → 结论：**难度曲线必须人工编排**（见下面的排期与 §4），自动化只能帮你出关与标参数。
- 迭代 20%：生成器 + 校验日志是**素材**，不是分数本身——必须配"版本对比"（见 §4 的 M12）。

**⚠️ 一个必须知道的边界（T5 实测）**：6×6 下 `贪心最小探测格集` 的中位数 = **1** —— 大多数混合关卡**只要 1 个探测格就能唯一确定**，真正在干活的是数织，探测格只是"封口"。**所以双线索的"咬合"在 6×6 尺度上偏弱**：
- **前 3 关不要用 4×4 / 5×5**（太小，咬合不成立），**直接从 6×6 起**；
- 想让两套线索真正互相咬合，**要在 7×7 以上**（`[未验证]`：T5 未测 7×7 以上的咬合强度）。

**核心循环与 3/30/180**：3 秒（探测一格、看到数字）；30 秒（第一次用"连续块"线索推出一格，发现两套线索咬合）；3 分钟（每关 60–150 秒，"再来一关"）。

**前 3 关钩子（官方 MVP 法）**
1. **6×6**、只有邻域数字（纯扫雷味，教会"探测看数"）
2. **6×6**、加入行列连续块线索，并**在这一关显式教学"我和 Meowdoku 的区别"**（"我懂了"）
3. **7×7**、设一个"看起来要猜、其实连续块线索给出唯一解"的骗局（"哦？有意思"）

**47 关变化轴 + 难度参数（修正后：只用可观测参数 + 人工曲线）**
| 维度 | 走向 |
|---|---|
| 尺寸 | 6×6 → 12×12（**不要用 4×4/5×5 开局**） |
| 雷密度 | `[实测]` **混合模式**的密度轴：6×6 / 6 探测格，雷数 5→7→9 = 无猜可解率 **65.3% → 62.0% → 57.3%**；8×8 / 13 雷，探测格 3→5→10 = **8.7% → 16.7% → 40.7%**（探测格越多越好解） |
| 探测格数 | 最强的难度杠杆（探测格 2→3→6→10 = 25.3%→34.7%→62.0%→83.3%） |
| 线索粗细 | 连续块越碎线索越强 |
| 新机制（每 5–10 关一个人工投放，并写进关卡数据） | ① 部分数字替代块线索 ② 双色雷（各自计数）③ 行列线索仅给其一 ④ "信息过期"格（若干步后重新暗掉）⑤ 只给全局雷总数 |

> ⚠️ v1 曾用"8×8/10雷 57.12% → 12雷 31.82%"来说明密度轴——**那是 T3 的纯扫雷基准，不是本方向的混合模式**，数字对但用错了地方（M3）。上面已换成混合实测值。

**生成 + 校验（构建期）**：随机布雷 → 生成两套线索 → **无猜逻辑求解器**（单点约束传播 + 子集规则 + 零格 flood-fill）证明唯一且无需猜测 → 不过关就重采样。`[实测]` 50 关 **0.10 s**。

**目标用户**：海外 35+ 逻辑谜题用户（与主办方 Sudoku / Meowdoku 同人群）。

**技术栈与交付**：零依赖 Canvas 2D + TypeScript + Vite + `vite-plugin-singlefile`（`[GitHub API]` 1,236★ / MIT / 2026-10-17 push）→ inlined `index.html` `[推断]` **40–150 KB 量级**（T2 的外推，不是实测打包产物；提交前以 `dist/index.html` 实际字节数为准）；无图片/音频文件（音效用 ZzFX `[GitHub API]` 804★ MIT 程序化合成）；存档 `localStorage` + try/catch 降级 + 内存兜底。

**AI Native 生产流程（全部构建期）**：P2 内容工厂（AI 批量出关卡数据，字符矩阵零字节美术）；**P3 本地求解器当"AI 教练"**（卡住 30 秒时算出"当前局面唯一的下一步逻辑结论"并高亮，不给答案）；P1 难度导演表（AI 离线把每关的可观测参数与首轮推导格数标成表，运行时按失误率决定降档）；P5 讲解库。⚠️ 运行时零网络请求。

**风险与工作量**：**9–13 人日**。风险：① 前 3 关认知负荷（靠渐进教学 + 6×6 起步解决）；② 7×7 以上咬合强度与唯一解校验成本 `[未验证]`，开工第一天自测；③ 可能被问"是不是 Meowdoku 变体"→ 用"约束类型不同"+ 上述实测数据正面回答。

## D2. 合牌接龙 —— 纸牌接龙 × 合成 ⚠️ 需修正

**一句话概念**：接龙牌桌上，**把两张同点数的牌叠在一起就会合成更高一级的牌**（♠3+♦3 → ♠4）。于是"合成"自动生产出接龙所需的递增序列——**你为了合成而接龙，也为了接龙而合成**。

**元素A × 元素B**
- 元素A（接龙）：同花色**递增**序列（顺序约束）+ 空列/翻牌的资源管理。
- 元素B（合成）：同值**合并**成更高值（数值约束）。
- **化学反应**：合成动作的产物恰好是接龙动作的输入（3+3=4，而 4 正是 3 后面缺的那张）→ **一个动作同时推进两条规则**。这是五个方向里机制耦合最紧的一个。

**评分映射**
- 玩法 50%：规则一句话说清，但每步都在权衡"这张牌用来接龙还是用来合成"。
- 关卡 30%：50 关 = 50 次**可解发牌**，每关带"求解器找到的解的步数"与三星。
- 迭代 20%：发牌器 + 求解器报告是素材；仍需"版本对比"。

**核心循环与 3/30/180**：3 秒（拖牌到同点数牌上 → 它升级了）；30 秒（升级后的牌刚好接上序列，产生连锁）；3 分钟（"这局差两步就通了"的接龙心流）。

**前 3 关钩子**
1. 单花色、6 张牌：教会"同值合并 → 升一级"
2. 加入空列与翻牌：教会"合并产物可以接序列"（"我懂了"）
3. 加一个"看起来该合并、其实该留着接龙"的取舍（"哦？有意思"）

**47 关变化轴**：花色数 1→4｜牌桌列数｜是否双副牌｜冻结牌（需先合成解冻）｜必合成次数配额｜步数上限｜额外目标（清空某列 / 合出 K）｜Joker 万能合成。每 5–10 关投放一个新机制，并在机制引入关**故意回落难度**。

**⚠️ 生成 + 校验（v1 的两个卖点已被 T5 实测打掉，必须改写）**
- ❌ **"逆向发牌、0 搜索"不成立**：从必胜终局做合法逆向游走，检查是否命中合法发牌配置 → 200 步 **0/12**、1000 步 **0/12**、5000 步 **0/12**（且逆向动作集是过度宽松近似，故 0/12 是**上界**）。逆向动作保可达性，但命中那个极窄目标是**目标导向搜索**，不是自由游走。
- ❌ **"难度代理 = 最少移动步数"不可实施**：12 局 BFS **12/12 全部撞上限**，只推进到深度 24–51 就烧掉 11.8万–35.1万节点（每局 10 s），**最优解一次都没算出来**。
- ✅ **替代方案（可落地）**：**随机发牌 + 求解器筛选**。`[实测]` 200 局中 89 局可解（**44.5%，是下界**，另有 111 局撞上限未判定），naive DFS **5,589 ms/局** → 凑 50 关 ≈112 局 ≈ **628 s**（一次性构建成本，可接受；换更好的启发式或复用已知可解发牌库能大幅下降）。
- 难度代理改为：**求解器找到的任意解长度** + **诱导性死路数量**（可计算），而不是"最少步数"。

**目标用户**：海外 35+ 纸牌/接龙用户。`[GitHub API]`（2026-10-21）`solitaire in:name` = **10,575**（v1 写 10,568，是 2026-10-20 的快照，**漂移 +7，非编造**——所有计数都应带抓取日期）；`solitaire merge in:name` = **3**（弱信号）。主办方有 **Jenny Solitaire** → 品类口味被自证，但"接龙×合成"不在他们产品线上，**撞车风险低**。

**技术栈**：同 D1。牌面用 Canvas 矢量绘制或 CC0 素材（`[权威来源]` kenney.nl 资产页实抓为 CC0）；**绝不复用任何商业游戏的美术/名称**（官方文档无版权条款，自证清单是唯一保护，constraints §2.5.5）。

**AI Native 生产流程**：P3 发牌器 + 求解器（构建期）；P5 讲解库（"这局 N 步能赢"）；P4 提示行为树（有限次数的"指出一步"）。⚠️ 运行时零网络请求。

**风险与工作量**：**15–20 人日**（v1 写 8–12 与"手感占工期一半以上"自相矛盾，已修正）。风险：① 发牌可解性筛选要跑 ~10 分钟构建，需缓存；② 接龙玩家对规则被改敏感 → 前 3 关必须极简；③ 手感（拖拽/吸附/撤销）占总工期一半以上。

## D3. 明牌叠消 —— 堆叠消除 × 可解性资源 ⚠️ 需修正

**一句话概念**：牌叠起来消三张（Vita Mahjong / 羊了个羊 玩法），但**"这一关还有多少条活路"从后台静默保证变成玩家看得见、能亲手改变的资源**——每走一步它都会变化，洗牌要花代价。

**元素A × 元素B**
- 元素A（堆叠消除）：只能取未被压住的牌，凑三张（或一对）消除 —— 已验证的亿级 MAU 品类。
- 元素B（可解性）：从"后台静默"升级为"前台可见、可消耗、可博弈"的资源。
- **化学反应**：玩家第一次能在消除类游戏里规划"我这一步会不会把自己走死"，正面回应该品类最出名的玩家抱怨（随机不可解）。

**⚠️ M4 修正：不要叫"剩余解数"**。在一般堆叠消除规则下，**精确计数剩余解是 #P-hard**，运行时算不出真值。玩家会把显示值当精确资源做决策，一旦与真实可达性矛盾 = **信任崩塌**。
→ **改成可精确计算的代理指标**（任选其一或组合）：
- **可选配对数**（当前可拿的牌里，能凑成三张/一对的组合数量）—— 精确可算，O(n) 级；
- **卡槽剩余容量**；
- **最长可连锁长度**；
- 或"距最近一次洗牌的步数"。
→ UI 上也别叫"解数"，叫 **"活路 / 余量"**，并在教学关说明它是**代理指标**而非承诺。

**评分映射**
- 玩法 50%：在已验证的高留存机制上做**规则层扭转**（不是换皮）——"活路"是全新的决策维度。
- 关卡 30%：难度 = **活路代理指标的下降速度** + 卡槽压力；50 关由逆向构造生成。
- 迭代 20%：生成器 + 活路曲线报告 + 版本对比。

**核心循环与 3/30/180**：3 秒（点三张一样的牌 → 消掉）；30 秒（发现"活路"在掉，开始挑顺序）；3 分钟（"再走两步就能翻盘"）。

**前 3 关钩子**：1. 单层、只有"同款三张"；2. 出现"活路"指示条并教它怎么变化（"我懂了"）；3. 一个"两条路都有活路，但一条会很快走死"的分岔（"哦？有意思"）。

**47 关变化轴**：层数（单层→多层压叠）｜**卡槽数 7→5（最强难度杠杆）**｜牌种数｜冻结/锁链牌｜特殊牌（万能/双倍）｜洗牌代价｜**活路代理指标的衰减率**。

**⚠️ 生成 + 校验（M5 修正）**
- v1 说"逆向摆牌 0 次搜索"——**忽略了卡槽容量约束**。而 v1 又把"卡槽 7→5"当成最强难度杠杆 → **最难的关卡恰恰最需要搜索**，两者矛盾。
- 落地写法：**逆向构造**保证"存在一条合法消除序列"（0 搜索，用于铺出初始布局）→ 再**用有界求解器**检查"在给定卡槽容量下仍可解"（有界、可失败即重采样）。**难度越高，这一步越可能需要搜索，要在构建期预算里算进去。**
- `[GitHub API]` 三消/堆叠/麻将配对的**开源关卡生成器几乎为零**（最高候选 1★ 级，多为无 license，oss.md §3.2）→ **必须自研，这是"≥50 关"的主要工作量与拿分点。**

**目标用户**：海外 35+ 消除类用户 —— 主办方两个亿级 MAU 作品都在这个桶里，**采纳风险最低、但撞车风险最高**（T5 判定：五个方向里最高）。

**差异化必须做在"活路可见化"上**：设计文档要明确写"这不是又一个 Tile Explorer/Vita Mahjong"，并给出**对比表**（他们：静默保证；我们：可见、可消耗、可博弈）。

**技术栈**：零依赖 Canvas 2D 即可；需要精灵动画/粒子时备选 **KAPLAY**（`[GitHub API]` 1,812★ MIT，`[实测]` ≈184.7 KB raw）或 **LittleJS**（`[GitHub API]` 4,307★ MIT，≈476.8 KB raw + 内置 ZzFX）。⚠️ **牌面必须自制或 CC0**。

**AI Native 生产流程**：P3 逆向构造器 + 运行时增量维护"活路"代理指标（O(n)，不解方程）；P1 难度导演表按失误率调卡槽数；P5 讲解库。

**风险与工作量**：**16–22 人日**（五个方向里最长）。风险：① 撞主办方拳头品类；② 活路指标的设计要"既诚实又有用"（显示要可解释，别做成黑箱）；③ 动画/手感多，容易超期。

## D4. 箭头推链 —— 箭头解谜 × 推箱子 ✅ 技术风险最低

**一句话概念**：点一下箭头，它沿自身方向滑到底；**撞到别的箭头就把对方推着走**。用"推动顺序"把目标块送进出口——顺序错了就锁死，但有无限撤销。

**元素A × 元素B**
- 元素A（箭头解谜）：点一下、沿方向滑到边界（Amaze Go! 的爽感来源，主办方最新黑马）。
- 元素B（推箱子）：推动物体的**顺序约束**（晚一步就推不动）。
- **化学反应**：加上"被推"之后，"点哪个箭头"从**单步直觉**变成**多步规划**，并能产生**连锁推动**的意外惊喜。

**评分映射**
- 玩法 50%：3 秒上手（点箭头它飞），30 秒出现"顺序"这一层深度。
- 关卡 30%：难度 = **BFS 最短点击序列长度**（客观、可排序）；每 5–10 关新增一种箭头类型。
- 迭代 20%：生成器 + 最短解报告 + "最优解回放"（教学彩蛋）。

**核心循环与 3/30/180**：3 秒（点箭头、看它滑行）；30 秒（第一次推动另一个箭头，连锁）；3 分钟（"我知道了，得先把那个移开"）。

**前 3 关钩子**：1. 一个箭头 + 一个目标块（教会滑行）；2. 引入"推到边界停下"的阻挡（"我懂了"）；3. 两个箭头互相推动，必须选对先点哪个（"哦？有意思"）。

**47 关变化轴**：网格尺寸｜箭头数量｜**可动块数（硬上限 4）**｜单向/双向/锁死/传送/需配对箭头｜目标数｜"必须最后才动"的依赖链。

**生成 + 校验**
- **反向回推**：从已完成终局往回施加逆推动作 → 生成即可解；难度 = BFS 最短点击序列长度 + 分支数。
- ⚠️ **红线**：`[实测]`（constraints §2.4B）完整 A\* 证明随箱子数爆炸：2 箱 0.007 s → 3 箱 0.045 s → **4 箱 0.220 s** → **5 箱 4.401 s 均值 / 12.598 s 最大，且 2/8 撞 400k 状态上限**。→ **可动块锁死 ≤4，用"最小步数阈值"筛难度，不做完整可解性证明。**
- ⚠️ **T5 补充的诚实边界**：上述 A\* 数字来自**推箱子语义**；箭头的"滑到底"语义分支因子更小，**理论上更便宜，但不能直接引用这组数字**——箭头规则落地后**必须重测一次**（`[未验证]`）。

**目标用户**：海外 35+ 空间解谜用户；Amaze Go! 是"上线<3月 MAU 破 2000万、霸榜 Google Play 免费前三"的黑马 `[官方原文]`；`[GitHub API]`（2026-10-21）`sokoban arrow in:name` = **0**（弱信号）。

**技术栈**：同 D1（箭头/方块是矢量，零图片）。**无限撤销是必需品**——它把"卡住"变成"再来一次"。

**AI Native 生产流程**：P3 反向生成器 + BFS 求解器（构建期算最短解，运行时只回放预存解序列）；P1 按"实际点击次数 vs 最短"给星级；P5 每关一句"这关考的是顺序"。

**风险与工作量**：**8–12 人日**（技术风险最低）。风险：① 贪心做"多箱子 + 完整证明"立刻撞 A\* 墙 → 严守 ≤4；② 空间解谜容易劝退休闲用户 → 无限撤销 + 宽裕步数松绑。

## D5. 通途数阵 —— 管道连线 × 数独式区域约束（替换原「合十升级」）

> T5 判定原 D5（合十升级）**建议淘汰**：它**天然没有关卡概念**（v1 自己承认要把"无关卡品类改造成 50 关"），且活在 2048（59,453 仓库）的影子里。替换为**管道×数独**：逆向生成不受全局资源约束、天然是网格关卡、且与 D1 的风险画像不重复。
> 合十升级降级为**备胎**（见 §3）。

**一句话概念**：像 Flow Free 一样把同色端点连起来、填满全盘且不交叉；同时**每个区域/行列还要满足数独式的"不重复"约束**——局部约束好填，全局连通难保，两者的张力就是难度来源。

**元素A × 元素B**
- 元素A（管道连线）：全局拓扑约束（连通、不交叉、铺满）—— 成熟全平台品类，且**生成即"解"，把解打乱即题面**。
- 元素B（数独式区域约束）：局部"不重复"约束。
- **化学反应**：**局部约束容易逐格填，全局连通难以事后修补** → 玩家必须"先规划整体走线，再满足局部不重复"，这是两种思维方式的真实冲突。

**评分映射**
- 玩法 50%：规则两句话（"连起来、填满、不交叉"+"每格数字/颜色不重复"），深度来自约束冲突。
- 关卡 30%：网格尺寸/端点数/约束密度都是**可观测参数**；**生成走反向构造**（先造合法解，再拆成题面）→ 可解性由构造保证。
- 迭代 20%：生成器 + 唯一性校验报告 + 版本对比。

**核心循环与 3/30/180**：3 秒（拖出一条线）；30 秒（发现"线占了这个格，那一行就不重复了"）；3 分钟（"差最后一条线"）。

**前 3 关钩子**：1. 3×3、一对端点、无区域约束（教会连线）；2. 4×4、加入"每行每色不重复"（"我懂了"）；3. 5×5、一个"为了满足不重复必须绕路"的盘面（"哦？有意思"）。

**47 关变化轴**：网格 4×4→9×9｜端点对数｜区域约束类型（行不重复 / 列不重复 / 宫不重复）｜预填格｜禁止交叉开关｜"必须经过特定格"。

**生成 + 校验**：**反向构造**——先在盘面上铺出满足全部约束的合法解，再隐藏它成为题面 → **0 搜索即保证至少一个解**。
⚠️ `[未验证]`：**解的唯一性**需要额外校验（可能要有限搜索）；T5 推荐本方向的理由是"逆向生成真的无全局资源约束 = 真的 0 搜索"，但**唯一性校验成本与规则解释成本都未实测**——这是本方向开工第一天的验证任务。规则解释成本（是否违背"3 秒上手"）是它最大的风险。

**目标用户**：海外 35+ 解谜用户；管道/Flow 类是全平台成熟品类，但**主办方作品表里没有管道类** → 口味契合度低于 D1–D4，撞车风险也低。

**技术栈**：同 D1（线条/SVG 或 Canvas 矢量，零图片）。

**AI Native 生产流程**：P3 生成器即 AI（"生成即保证可解"，提示只需回放已知解的第一步）；P1 按盘面参数排序难度；P5 每关一句考点讲解。

**风险与工作量**：**8–12 人日** `[推断]`（未经独立实测）。风险：① **规则解释成本**（两套约束同时讲，可能超出"3 秒上手"）；② 唯一性校验成本 `[未验证]`；③ 与主办方口味契合度不及前四个。

## 3. 备胎：合十升级（数字配对 × 2048 合成）

**一句话**：盘面是 1–9 的数字，**两张同值、或两张加起来等于 10 的牌可以合成一枚更大的牌**（10→20→40…），目标是合出该关的目标值。消除条件不是"相等"，而是"凑出一个和"。

**为什么降为备胎**：① **它天然没有关卡概念**，必须把"无限局"改造成"每关 = 盘面 + 目标值 + 步数上限"，这是改造而非继承；② 母体 2048 极拥挤（`[GitHub API]` 59,453 仓库）；③ 主办方作品表里没有数字配对口味的代表作（该品类证据 `[未验证]`）。

**但它有一个别人没有的优点**：**实现最简单、手感最快能验证**（`[推断]` 6–9 人日）。如果你担心前三天的原型不够好玩，**可以先用它做"手感探针"**——3 天内就能知道"凑十 + 升级"到底爽不爽；如果爽，再决定是否改造成 50 关制。

## 8. 一句话总结

**选一个"两个成熟机制的规则层融合"，把 50 关交给构建期的生成器，把难度曲线交给人，把 AI 的价值放在"难度导演表 + 本地求解器教练 + 版本对比式迭代文档"上，绝不把核心玩法押在运行时的大模型上。** 首选 **D1 雷线谜图（扫雷×数织）**——它的融合已被独立实测证实（单用任一半 0%/13.8%，合用 60.2%）；今天先发邮件问清提交平台与参赛资格，再用 3 天做出 **6×6 起**的 3 关。**能不能玩下去，第 3 关就告诉你了。**
