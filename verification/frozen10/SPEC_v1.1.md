# 雷线谜图 v0.1 — 规则与关卡数据格式（冻结版）

> 用途：3 关体验版原型的**唯一接口契约**。UI 与关卡生成器都必须严格遵守本文件；任何规则分歧以本文件为准。
> Owner：lead｜冻结时间：2026-10-21

## 1. 玩法定义

网格 N×N，每格是**雷**或**安全格**（初始全部未翻开）。
**目标：把所有格子分类完毕 —— 所有安全格已翻开，且所有雷已插旗。**

### 两种操作（界面提供模式切换：探格 / 插旗）
| 操作 | 行为 |
|---|---|
| **探格**（点未翻开的格） | 若是**雷** → 扣 1 条命，该格变为"已翻开的雷"（等同已标出，不重复扣命）；若是**安全格** → 翻开并显示**邻域雷数**（周围 8 格的雷数量，0–8）；若该数为 **0** → 自动 flood fill 展开相连的 0 区，并翻开其边界上的数字格 |
| **插旗**（点未翻开的格） | 标记 / 取消标记为雷（不影响命数） |

### 线索
1. **邻域数字**：翻开的安全格上的数字（永久可见）—— 来自"扫雷"。
2. **行列连续块线索**（**仅第 2、3 关显示**，第 1 关不显示）：每行左侧、每列上方显示该行/列中**连续雷块的长度序列**——来自"数织"。
   - 例：`2 1` = 先 2 个连续雷、至少 1 个安全格、再 1 个雷。
   - 该行/列没有雷 → 显示 `0`。
3. **开局赠送**：每关给定一个已翻开的 **0 格**（`opening`），进入关卡即自动 flood fill，让玩家一开始就有信息。

### 胜负
- **胜利**：所有安全格已翻开 **且** 所有雷都已"标出"——*插旗* 或 *已被探爆（翻开的雷）* 都算标出。
  - 修订 v1.1（2026-10-21）：原措辞为"所有雷已插旗（严格全覆盖）"。独立复核指出实现里"踩爆但未插旗"的雷也计入胜利判定，与本文件字面冲突。经确认**实现的做法是正确的**：踩爆的格子已经翻开，界面不允许对其插旗，若胜利要求严格插旗，则"踩爆过的雷"会让该局**永久不可胜**。故此处修订为与实现一致，并明确"探爆 = 标出"。
- **失败**：命数归 0（默认 3 条命）。
- 状态栏显示：`已翻开 a/b · 已标雷 m/M · 剩余命数 ❤n`，其中 `m` 同样包含已探爆的雷。
- 补充说明（v1.1）：**已插旗的格子会挡住 flood fill**（与经典扫雷一致）——数字为 0 的格连锁展开时，已插旗的格子不会被自动翻开，需要玩家自行取消插旗后再探。这不是缺陷，是这个玩法的既有惯例；实现与复核项以此为准。

## 2. 关卡数据格式（JSON，单一事实源）

```json
{
  "id": 1,
  "name": "第 1 关 · 学会看数字",
  "size": 6,
  "mines": [[r, c], [r, c]],
  "showRuns": false,
  "rowRuns": [[2], [], [1, 1]],
  "colRuns": [[1], [3]],
  "opening": [2, 2],
  "lives": 3,
  "teach": "点开的数字 = 它周围 8 格里有几颗雷。",
  "technique": "single-point"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 1..3 |
| `name` | string | 关卡标题（含教学语义） |
| `size` | int | 边长 N（第1关 6，第2关 6，第3关 7） |
| `mines` | `[r,c][]` | 雷的坐标（0-based）。**仅用于胜负判定**，界面不得直接展示 |
| `showRuns` | bool | 是否显示行列连续块线索（第1关 `false`，第2/3关 `true`） |
| `rowRuns` | `number[][]` | 每行的连续雷块长度序列；`[]` 或 `[0]` 表示该行无雷（**统一用 `[]`**） |
| `colRuns` | `number[][]` | 同上，每列 |
| `opening` | `[r,c]` | 已翻开的 0 格（**必须保证邻域雷数 = 0**） |
| `lives` | int | 命数，默认 3 |
| `teach` | string | 进入关卡时显示的提示（可为空串） |
| `technique` | string | 该关主要考察的推理技巧标签（用于迭代文档） |

**一致性要求（生成器必须自证）**：`rowRuns`/`colRuns` 必须与 `mines` 完全一致；`opening` 必须是安全格且邻域雷数 = 0；每关必须**唯一解且无需猜测即可完成**。

## 3. 第 1/2/3 关的教学意图（必须体现在关卡设计里）

| 关 | 尺寸 | 线索 | 教学意图 |
|---|---|---|---|
| **1** | 6×6 | **只有邻域数字** | 教会"翻开看数字"（纯扫雷味）。必须**只靠动态探格**就能零猜测通关 |
| **2** | 6×6 | 邻域数字 **+ 行列连续块** | 教会"行/列上的连续块数字也在告诉你雷在哪"（"我懂了"） |
| **3** | 7×7 | 邻域数字 **+ 行列连续块** | 有一个必须是"**看起来要猜、其实连续块线索给出唯一解**"的关键步（"哦？有意思"） |

## 4. UI 验收标准（T7）

1. **单文件**：`game/index.html` 自包含、无外部依赖、**无任何网络请求**，`file://` 双击即玩。
2. **手机竖屏可用**：棋盘自适应宽度，无横向滚动；pointer/touch 与鼠标点击都支持。
3. **模式切换**（探格/插旗）清晰可见，避免误触；提供 **重玩本关**。
4. **状态栏**：已翻开 a/b · 已标雷 m/M · 剩余命数 ❤n。
5. **教学文案**：进入关卡显示 `teach`；第 3 关 `teach` 为空（不提示）。
6. 胜利后显示 **"下一关"**（第 3 关通关显示"全部通关"）；失败显示"重来"。
7. **关卡数据内嵌**在这个注释块之间，便于 Lead 注入真实数据：
   ```
   /* LEVELS_INJECT_START */
   const LEVELS = [ /* 占位数据 */ ];
   /* LEVELS_INJECT_END */
   ```
8. 界面**不得展示 `mines`**。

## 5. 生成器交付标准（T6，lead）

- `tools/generate_levels.py`：生成器 + **逻辑求解器**（同时使用"邻域计数传播"与"数织行/列枚举"两种推理），产出并校验 3 关。
- 校验必须自证：唯一解、零猜测可完成、线索与 `mines` 一致、`opening` 为 0 格。
- 产出 `tools/levels.json`（**将注入 HTML 的同一份数据**）与 `tools/report.md`（每关的推理序列、步数、接受/拒绝统计 → 迭代文档素材）。

## 6. 独立复核标准（T8）

复核者必须**独立实现**校验（不得复用 lead 的求解器代码），确认：
1. 每关在给定线索下**解唯一**（枚举所有与线索相容的布雷方案）。
2. 每关**零猜测可完成**（模拟玩家：始终存在可证明的安全格或雷）。
3. `rowRuns`/`colRuns`/`opening`/`mines` **互相一致**。
4. 阅读 `game/index.html`，确认其**实现了本文件 §1 的规则**（flood fill、命数、插旗、胜利条件、第1关不显示 run 线索）。
