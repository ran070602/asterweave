## 规则（与已上线的「命数评价」一致）

- **星星 = 通关剩余望远镜数**：零失误 ★★★、失误 1 次 ★★☆、失误 2 次 ★☆☆。
- **已通关必然 ≥1 星**：第 3 次失误即判负，所以"通关却 0 星"不存在。
  例外是**旧存档**——评价功能上线前通关的关卡没有记录，显示 0 星，重玩一次即补上。
- 金色 **⏱** 仍只是"时间达标"标记，**不参与星数**（"快"与"稳"是两条正交能力）。
- **无尽冲分**不参与（它有自己的望远镜经济与分数）。
- **重玩也计时**（2026-10-28 起）：第 11 关起重玩同样限时、超时同样判负——否则满分就成了没有时间压力的刷分。
- **关卡页只展示最高成就**：拿过三星就永远三星，后续重玩拿一星/二星不影响展示。

## 为什么用星星而不是"完美"两字

1. 星星是**通用语言**，不用解释；且天然支持"三星/二星/一星"的**累积目标**（★ 96/264）。
2. 与现有金 ✦/金 ⏱ 的层级不冲突：**星星在格子底部**，左上 ⏱、右上 ✓/🔒 保持原样。
3. 结算弹窗用星星 + 「三星！」胶囊 + ✓ 清单，把"为什么得这几颗星"**逐条摊开**——这是参考图最有价值的一点：玩家能看懂自己差在哪。

## 落地代价（若要实现）

- 数据**不用新增**：现有 `progress.bestLives`（0–3）直接映射星数。
- 关卡格子建议用 **CSS 三重 radial-gradient 画星星**（或 SVG 背景），**不新增子节点**——否则关卡按钮的 `textContent` 会从 `"5"` 变成 `"5★★☆"`，影响现有测试与无障碍标签。三星/二星/一星用 `.s3/.s2/.s1` 三个类切换。
- 结算弹窗要新增星星行与清单 → 会影响 `v17`（结算条）、`v18`（揭晓/弹窗）等套件，需同步更新并 `python tools/run_tests.py` 全绿复跑。
- 参考图里的「已收藏 · 日期」需要一个新字段（如 `progress.collectedAt[关卡]`）；不想要日期就沿用现有的「已收入图鉴」。
