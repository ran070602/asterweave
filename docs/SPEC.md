## 1. 玩法定义

网格 N×N，每格是**雷**或**安全格**（初始全部未翻开）。
  
**目标：把所有格子分类完毕 —— 所有安全格已翻开，且所有雷已插旗。**

### 两种操作（**无模式切换，按设备区分**）

- 📱 触摸：**轻触 = 观测**（即时）；**长按（~380ms）= 标记**
- 💻 鼠标：**单击 = 观测**（即时）；**右键 = 标记**（不做双击标记：双击的第一击会先探测，语义有歧义，故移除）
- ⌨️ 键盘：Enter = 观测；空格 = 标记

| 操作             | 行为                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **观测**（点未翻开的格：手机轻触 / 电脑单击） | 若是**雷** → 扣 1 条命，该格变为"已翻开的雷"（等同已标出，不重复扣命）；若是**安全格** → 翻开并显示**邻域雷数**（周围 8 格的雷数量，0–8）；若该数为 **0** → 自动 flood fill 展开相连的 0 区，并翻开其边界上的数字格 |
| **标记**（手机长按 ~380ms / 电脑右键） | 标记 / 取消标记为雷（不影响命数）。手机长按被消费掉后抬起不会再观测；手指划动超容差（12px）则取消                                                                                                                   |

### 线索

1. **邻域数字**：翻开的安全格上的数字（永久可见）—— 来自"扫雷"。
2. **行列连续块线索**（**由关卡数据的 `showRuns` 决定**；10 关初版中第 1–3 关不显示、第 4–10 关显示）：每行左侧、每列上方显示该行/列中**连续雷块的长度序列**——来自"数织"。
   - 例：`2 1` = 先 2 个连续雷、至少 1 个安全格、再 1 个雷。
   - 该行/列没有雷 → 显示 `0`。
3. **开局赠送**：每关给定一个已翻开的 **0 格**（`opening`），进入关卡即自动 flood fill，让玩家一开始就有信息。

### 胜负

- **胜利**：所有安全格已翻开 **且** 所有雷都已"标出"——*插旗* 或 *已被探爆（翻开的雷）* 都算标出。
  - 修订 v1.1（2026-10-21）：原措辞为"所有雷已插旗（严格全覆盖）"。独立复核指出实现里"踩爆但未插旗"的雷也计入胜利判定，与本文件字面冲突。经确认**实现的做法是正确的**：踩爆的格子已经翻开，界面不允许对其插旗，若胜利要求严格插旗，则"踩爆过的雷"会让该局**永久不可胜**。故此处修订为与实现一致，并明确"探爆 = 标出"。
- **失败**：命数归 0（默认 3 条命）。
- 状态栏显示：`已翻开 a/b · 已标雷 m/M`，**命数以 3 颗望远镜图形展示并依次熄灭**——`❤❤❤` → `❤❤♡` → `❤♡♡` → `♡♡♡`（命数归零即失败）；`m` 同样包含已探爆的雷。望远镜组必须有 `aria-label`（如「剩余命数 2 / 3」），不要逐颗朗读符号。
- 补充说明（v1.1）：**已插旗的格子会挡住 flood fill**（与经典扫雷一致）——数字为 0 的格连锁展开时，已插旗的格子不会被自动翻开，需要玩家自行取消插旗后再探。这不是缺陷，是这个玩法的既有惯例；实现与复核项以此为准。

## 2. 关卡数据格式（JSON，单一事实源）

```json
{
  "id": 1,
  "name": "第 1 关 · 学会看数字",
  "size": 6,
  "mines": [[r, c], [r, c]],
  "showRuns": false,
  "rowRuns": [[2], [], [1, 1]],
  "colRuns": [[1], [3]],
  "opening": [2, 2],
  "lives": 3,
  "teach": "点开的数字 = 它周围 8 格里有几颗雷。",
  "technique": "single-point"
}
```

| 字段          | 类型           | 说明                                                                      |
| ----------- | ------------ | ----------------------------------------------------------------------- |
| `id`        | int          | 1..N（N = 关卡总数）                                                          |
| `name`      | string       | 关卡标题（含教学语义）                                                             |
| `size`      | int          | 边长（10 关初版：6 → 7 → 8）                                                    |
| `mines`     | `[r,c][]`    | 雷的坐标（0-based）。**仅用于胜负判定**，界面不得直接展示                                      |
| `showRuns`  | bool         | 是否显示行列连续块线索（10 关初版：第 1–3 关 `false`，第 4–10 关 `true`；**以数据为准，不由关卡序号硬编码**；**现行 88 关：88/88 全为 `true`**——第 1 关（重做后）起就显示行列线索，`tools/check_levels.py` 据此要求全部为 true） |
| `rowRuns`   | `number[][]` | 每行的连续雷块长度序列；`[]` 或 `[0]` 表示该行无雷（**统一用 `[]`**）                           |
| `colRuns`   | `number[][]` | 同上，每列                                                                   |
| `opening`   | `[r,c]`      | 已翻开的 0 格（**必须保证邻域雷数 = 0**）                                              |
| `lives`     | int          | 命数，默认 3                                                                 |
| `teach`     | string       | 进入关卡时显示的提示（可为空串）                                                        |
| `technique` | string       | 该关主要考察的推理技巧标签（用于迭代文档）                                                   |

**一致性要求（生成器必须自证）**：`rowRuns`/`colRuns` 必须与 `mines` 完全一致；`opening` 必须是安全格且邻域雷数 = 0；每关必须**零猜测可完成**——即模拟一个只做可靠推理、绝不猜的玩家，每一步都存在可证明安全（或可证明是雷）的格子，直到全盘判定完毕。

> **关于"唯一解"的口径（v1.2 修正）**：本文件原写作"每关必须唯一解"。独立复核指出这**不是**本作成立的判据，且与本作实际形态不符：
>
> - **零猜测可完成 ≠ 开局线索下解唯一**。扫雷类玩法靠**探格**不断获得新数字，玩家的收敛是路径依赖的；"开局那一眼的线索"本身完全可能有多个相容布雷方案。
> - 实测（T13 独立复核，10 关初版 v0.3）：**26 / 1 / 1 / 8 / 1 / 2 / 20 / 68 / 1 / 11**（按第 1–10 关顺序）；即第 **1、4、6、7、8、10** 关开局线索有歧义，其余为 1。**这些关卡全部仍然零猜测可完成**。
> - 因此契约要求是：**必须零猜测可完成**；开局相容方案数**必须如实披露**（>1 的关卡不得被描述成"唯一解"）。

## 3. 难度带与教学意图（10 关初版；88 关沿用同一分段逻辑）

难度轴：**是否需要第二套线索 → 棋盘尺寸 → 雷数与线索结构**。

| 关            | 尺寸        | 线索               | 教学意图                                                         |
| ------------ | --------- | ---------------- | ------------------------------------------------------------ |
| **1**（首关即引入数织） | 6×6       | **邻域数字 + 行/列连续块**       | 教会"翻开看数字"。必须**两条线索一起用**才能零猜测通关（**数织贡献 = 2 格，数织必需**）                      |
| **2**（引入数织）  | 7×7       | 邻域数字 **+ 行列连续块** | 立刻上融合：教会"行/列的连续块数字也在告诉你雷在哪"；**数织贡献要求 ≥6 格**（实测 9 格），保证不是贴标签 |
| **3–5**      | 6×6 → 7×7 | 两者都有             | 交叉推理；**只用邻域推理会推死、必须用数织线索**                                   |
| **6**（结构性线索） | 7×7       | 两者都有             | `0` 行/列（生成时强制包含至少一条空行或空列，保证该教学点真实存在）                         |
| **7–10**     | 8×8       | 两者都有             | 尺寸与密度收尾，长链推理                                                 |

> 教学文案（`teach`）**只在首次引入新机制时非空**（10 关初版：第 **1、2、6** 关非空；**现行 88 关：第 `1、2、6、7` 关非空**——1 双线索入门、2 线索更密、6 杂星归属、7 北斗七星），其余留白。

## 4. UI 验收标准（T7）

1. **单文件**：`game/index.html` 自包含、无外部依赖、**无任何网络请求**，`file://` 双击即玩。
2. **手机竖屏可用**：棋盘自适应宽度，无横向滚动；pointer/touch 与鼠标点击都支持。
3. **无模式切换**：手机「轻触观测 / 长按标记」、电脑「单击观测 / 右键标记」。**操作提示放在棋盘正上方（紧跟「第 N/88 关」那行）并加粗突出**；长按不弹系统菜单（-webkit-touch-callout:none）。
4. **结算条按钮按结果区分**：**失败**时结算条只给「↻ 重来本关 / 换个关卡」，**不提供回看按钮**（失败 modal 已经弹过，重复打开没有信息量）；**通关**时提供「★ 图鉴详情」（用于回看本关星座）与「下一关 →」。
5. **同一时刻只出现一个「重来本关」**：游戏进行中显示常驻重玩按钮；一旦结算（通关/失败）出现，常驻按钮隐藏，只保留结算 modal / 结算条里的入口。
6. **首次打开**显示一次**主页**（v2.10 起为「闯关/无尽」双模式卡，见 §4.16；不再限定"第 1 关"），关闭后写入本地 introSeen，之后不再自动弹；顶栏另有常驻入口可随时打开（游戏中即暂停菜单）。
7. **状态栏**：已翻开 a/b · 已标记 ★ m/M · **3 架望远镜表示命数并依次熄灭**（见 §1）。
8. **教学文案**：进入关卡显示 `teach`；`teach` 为空串时**不显示教学条**（不出现空条）。
9. **通关用 modal 收尾**：胜利时弹出居中 modal（遮罩 + 卡片），标题如「第 N 关 · 通关！」，按钮 **「重来本关」** 与 **「下一关」**；**最后一关**标题改「全部通关！」且不出现点了没反应的死按钮（禁用或隐藏，判断基于 `LEVELS.length`）。键盘可达（Tab / Enter，Esc 行为自定但若可关闭则需有再次打开的入口），手机竖屏卡片自适应、按钮 ≥44px、遮罩阻挡棋盘误触。失败时**复用同一 modal**（标题如「踩到雷了」+「重来本关」），且不改变失败后的规则行为。
10. **关卡选择与进度**：支持任意关数（三态：已通关 / 当前 / 未解锁）与 `localStorage` 进度记忆（读写包 `try/catch`，不可用时静默降级为内存进度）。
11. **关卡数据内嵌**在这个注释块之间，便于 Lead 注入真实数据：
   ```
   /* LEVELS_INJECT_START */
   const LEVELS = [ /* 占位数据 */ ];
   /* LEVELS_INJECT_END */
   ```
12. 界面**不得展示 `mines`**。
13. **意见箱（v2.2）**：顶部「✉ 意见」打开；`textarea` + 自动附带的环境信息（版本/关卡号与星座名/盘面/命数/状态/设备/UA 摘要/视口，可勾选关闭）+ 三个带出入口：
    - **复制反馈**（clipboard API，失败退 `execCommand`，再失败则选中文本让玩家手动复制）
    - **导出 feedback.txt**（`Blob` + `URL.createObjectURL`，离线可用）
    - **✉ 查看作者邮箱**（弹居中 modal 显示真实邮箱地址，地址后紧跟一个**「复制」小按钮**；**不提供二维码、也不提供 `mailto:` 链接**——真机上 App 关联不可靠，实测不好用）
    - **隐私**：输入内容**不落盘**（不写 `localStorage`、不写任何键），只在当前面板的内存里；点「复制 / 导出」才离开浏览器，**不得自动上传**。界面须写明这一点。
    - **详情默认收起**：环境信息不得默认平铺在面板里（占位置）；只显示一行「☑ 附带关卡与设备信息　查看」，点「查看」在**屏幕中央**弹小 modal（`position:fixed` 居中，不许向下展开——避免玩家视线跟着下移）；未勾选时 modal 须明示「不会附带」。
    - **离线自包含不变**：全页仍**零外部引用**（`http(s)://`、`fetch(`、`<link`、`import(` 一律为 0）；如启用二维码，必须是内联 data URI。

14. **星座详情海报（v2.5）**：点开某个已观测星座时，详情卡的结构是
    - **左上角**：旧的小星图（`constSvg`）缩小为缩略图（`.sky-thumb`，≤92px），右侧并列名称/等级/坐标/天区/面积/最亮星；
    - **主视觉**：一整张**星座海报**（内联 SVG，`viewBox 640×380`）——深空渐变背景 + 银河带 + 确定性星尘、
      大标题（英文名 + 中文名）、按视星等定大小的金色星点与连线、**最亮 ≤5 颗星的英文名标注**（带深色描边避免糊）、
      左下角信息卡「可见：<半球>」与「最佳观赏：N 月」；
    - **版式硬要求（v2.6）**：顶部 `0–74px` 是**标题带**，图形一律从 74px 以下开始（**标题不得压住星点或标注**）；
      图形按**星点包围盒**等比自适应放大（占可用高度 100%，实测图形框 294/380 ≈ 77%）；
      星名标注做**二维矩形避让**（左右两侧 × 多档纵向偏移），**放不下就不画**（宁缺不叠），实测 88 个星座标注零重叠；
    - **不得新增外部资源**：海报是内联 SVG（无 `<img>`、无外链）；
    - **未观测的星座一律不出海报、不泄露星名**（与 §4.11 图鉴条款一致）。
    - 观赏月份口径：午夜上中天（太阳赤经 = 目标赤经 + 12h，太阳每 2h ≈ 1 个月、0h ≈ 3/21）再后延约 1.5 个月（傍晚即高悬）。
      可见半球口径：赤纬 ≥ +20° 记「北半球」、≤ −20° 记「南半球」、其间记「南北半球都可看」。

15. **图鉴 3D 天球（v2.7）**：星座图鉴默认是**可旋转的 3D 天球**，并提供「2D 投影」切换（选择写入 `progress.sky3d`，默认 3D）。
    - **实现约束**：**不得引入任何 3D 库**（无 three.js 等）；用内联 SVG + 自写的「球面坐标 → 旋转 → 透视投影」，保持单文件、离线、零外部引用。
    - **天文正确性**：星座位置由真实赤经/赤纬（`tools/sky.json` 的 `ra`/`dec`）投影到单位球面；绘制**天赤道环**（加粗）、赤纬 ±30°/±60° 圈、每 2h 一条赤经经线；
      **银道带**用银河北极（RA 12h51m / Dec +27.13°）生成的大圆近似。
    - **深度线索**：图形按"远→近"排序绘制（画家算法）；远侧网格线更淡、星座点更小更暗，近侧更大更亮。
    - **文字与保密**：**只有正面半球（`z > 0.12`）且已观测的星座显示名字**；**未观测星座只有暗点 + 无名字**，不得泄露任何星图信息（与 §4.11 一致）。
    - **交互**：拖动 = 转动天球（偏航 + 俯仰，俯仰夹在 ±1.45 rad）、滚轮/双指 = 缩放（0.75–2.6×）、双击 = 复位；点选星座仍打开 §4.14 的详情海报；
      季节筛选 = 只显示该季节星座并把该季节赤经带转到正面中心。
    - **自转**：图鉴打开时缓慢自转（约 1.6°/s，≈25fps 节流）；**按下即停**、松手约 2.4 秒后恢复；**`prefers-reduced-motion` 下不自转**；关闭图鉴即停止（不得在后台空转）。
    - **健壮性**：`requestAnimationFrame` 回调若不带时间戳，须按 ~16ms/帧估算，不得让角度变成 `NaN`。

16. **主页 / 模式选择（v2.10；v2.8 起为「入场页」）**：**首次打开先给主页**（复用 `#introOverlay` 容器），而不是直接给一堆格子。
    - 内容：品牌「星织 / ASTERWEAVE」+ 一句定位 + 玩法要点一行 + **模式卡**。
    - 模式卡：**继续当前进度**（`#homeResume`，仅当"有可继续的对局"时显示：无尽本轮进行中，或闯关棋盘**已动过**）、
      **闯关模式**（`#homeCampaign`）、**无尽冲分**（`#homeEndless`）；无存档时另有「从第 1 关开始」。
    - `progress.introSeen` 记录"已看过主页"，**老玩家不再自动弹**；顶栏 **常驻主页入口**（`#homeBtn`），
      游戏中点开即**暂停菜单**：打开时暂停本关倒计时（`openHome(true)` → `stopClock()`），关闭后**恢复**（不吞时间）。
    - 从无尽切到闯关会**先结算本轮**（分数入账）再离开，不静默丢弃成绩。
    - 验收：**从打开到能点格子 = 1 次点击**；模式卡在 360×640 / 390×844 / 1280×800 完整在视口（极矮视口走内部滚动兜底）。

17. **限时关卡（v2.10，强制；第 11 关起）**：`TIMED_FROM = 11`（1-based）。**第 1–10 关不限时**。
    - **两个时间**：**目标时间** `levelTargetSec = round((15 + 0.99×安全格 + 2.2×雷数) / 5) × 5` 秒（= 达标线，决定金色 ⏱）；
      **硬限时** `levelLimitSec = round(levelTargetSec × TIME_GRACE / 5) × 5`（`TIME_GRACE = 1.35`）——**状态栏倒计时显示的是硬限时**。
    - **倒计时从"第一次操作"开始**：未落子时只显示「限时 m:ss」（`timer idle`），不倒计时，避免"手还没动就掉时间"。
    - 状态栏计时条显示**剩余时间**「⏱ m:ss」；剩余 ≤ `max(20, 限时×20%)` 转黄（`warn`）、≤ 10 秒转红并脉动（`danger`）。
    - **超时即判负（强制，无开关）**：`status = 'lost'`、弹窗标题「**⏱ 超时**」，**不扣命**（与踩雷失败明确区分）。
    - **达标**：通关耗时 ≤ 目标时间 → `progress.timeOk[关卡下标] = 1`，并记录 `progress.best[关卡下标]`（最快用时秒）。
    - **关卡面板（`#lvGrid`）图标规则**：**第 11 关起每一关都带 ⏱** —— **包括"未解锁/锁住"的关卡**，与已解锁关卡保持一致，
      让玩家在选关时就能看出"从第 11 关开始都是限时"；未解锁关卡同时保留 🔒（`locked` 与 `timed` 并存，⏱ 在左上、🔒 在右上）。
      达标关卡的 ⏱ 为**金色**（`timeok`，CSS 规则排在 `timed` 之后以覆盖）。第 1–10 关不带 ⏱（显式 `untimed`）。
    - **无尽模式不套用闯关的限时机制**：`timeIsTimed()` 在无尽下恒为 false——不写闯关的 `best` / `timeOk`、不按闯关目标时间判负。
  **但无尽每局有自己的限时**（见 §18）：`endlessLimitSec()` = 该题目标时间 × 分档系数（0.85/0.90/0.95/1.00），夹在 `ENDLESS_TIME_MIN = 25` 与 `ENDLESS_TIME_MAX = 210` 秒之间；**超时扣 1 架望远镜并跳过本题**（不结束本轮）。

18. **无尽冲分模式（v2.10）**：与闯关并行，入口在**主页模式卡**（`#homeEndless`）。
    - **状态**：`document.body.dataset.runMode = 'endless'`；隐藏「关卡」按钮、显示「■ 结束本轮」。
    - **望远镜（=命数）**：开局 **2 架**（2026-10-26 用户决定：在每题限时的背景下给 2 架容错），每通关 **3 题 +1 架**，上限 **3 架**；失误 **−1 架**且连击归零；
      **用尽最后一架即结束本轮**（望远镜数 = 可承受的失误次数）。超时同样 **−1 架并跳过本题**（若此时已为 0 架则本轮结束）。
    - **抽题**：从**无尽专用题库**（`tools/endless_bank_full.json`，88 星座 × 2 盘面 = **176 题**，尺寸金字塔 6/7/8/9/10 各 22、11×11 66；
      与闯关同星座的盘面不重复）按盘面尺寸分 4 档（6–8 / 9 / 10 / 11），每档一把“抽卡袋”（抽完不放回，抽空重洗）；
      档位随题号推进（1–2 题小盘、3–5 题中盘、6–9 题大盘、第 10 题起超大；第 4 题起允许 ±1 波动，第 6 题前不放大盘）。
    - **每题限时**：`限时 = round(levelTargetSec(该题) × 档位系数 / 5) × 5`，档位系数 **A 0.85 / B 0.90 / C 0.95 / D 1.00**
      （闯关硬限时用的是 `TIME_GRACE = 1.35`），下限 **25s**、上限 **210s**。经题库真实解题步数折算 ≈ **3.0–4.5 秒/步**（大盘更宽松）。
    - **记分（只增不减）**：每题通关 `+ 100 + max(0, 盘面边长 − 5) × 10 + 25 × min(连击, 20)`（含**盘面尺寸加成**）；**失误不掉分、时间也不扣分**；
      结算总分 `= 通关得分 + 多得的望远镜 × 200`（**开局赠送的 2 架不计分** —— 否则什么都不做也能得 400 分，2026-10-26 用户指出并修正），
      并在结束页**列出得分明细**。
    - **计时**：本轮总时长为**暂停感知**（揭晓 / 切题 / 打开主页时暂停）；每题用时用于统计"最快一题"；
      与闯关的目标时间、达标标记**完全隔离**。
    - **揭晓**：走快速版 `startBoardReveal(true)`，**不弹结算弹窗、不显示底部条**，揭晓结束 900ms 后**自动进下一题**。
    - **结束页**：标题「本轮结束」+ SCORE 大字 + 得分明细 + 本轮第 N 题 / 通关数 / 最长连击 / 最快一题 / 本轮用时 +
      最高分与最长连击记录 + 规则说明；按钮「♾ 再来一轮」「← 回到闯关」「☰ 回到主页」（最高分、最长连击、最快一题**永久保存**；2026-10-26 起不提供清零入口）。
    - **独立存档**：`progress.endless = { best, bestStreak, fastestMs, runs }`；**不得写入 `progress.cleared` / `progress.last`**，
      也不得出现闯关的"命数耗尽"结算文案。

## 5. 生成器交付标准（T6/T10，lead）

- `tools/generate_levels.py`：生成器 + **逻辑求解器**（同时使用"邻域计数传播"与"数织行/列枚举"两种推理），**曲线驱动批量生成**（10 关初版 → **现行 88 关**）。
- 校验必须自证：**零猜测可完成**、线索与 `mines` 一致、`opening` 为 0 格且开局展开 ≥5 格、教学带意图符合（教学带必须"仅邻域推理可通关"）。
- 开局相容方案数：不含连续块线索的关卡用**精确枚举**给出确切数字；含连续块线索的组合空间过大时**如实标注"未判定"**，由独立复核补测。
- 产出 `tools/levels.json`（**将注入 HTML 的同一份数据**）与 `tools/report.md`（每关的推理序列、步数、接受/拒绝统计、相容方案数 → 迭代文档素材）。
- 意见箱素材：`tools/feedback.json`（邮箱 / 表单链接 / 版本）→ `tools/build_feedback.py` 离线生成
  `tools/feedback_qr.json`（邮箱/`mailto:`/版本；默认不生成二维码，需要时 `--qr`），由 `tools/build_release.py` 注入 `FEEDBACK_INJECT` 块。
- 发布打包：`tools/build_release.py` 产出 `dist/<姓名>-游戏本体/index.html` 与 `<姓名>-游戏本体.zip`（**ZIP 根目录即 `index.html`**，符合提交平台要求；ZIP 内另附 `README.txt`，内容取自 `tools/README_source.txt`，说明玩法/操作/离线运行），并写出 `dist/build_manifest.json`（含各输入/输出的 sha256）。

## 6. 独立复核标准（T8/T11）

复核者必须**独立实现**校验（不得复用 lead 的求解器代码），确认：

1. **每关零猜测可完成**（模拟玩家：每一步始终存在可证明的安全格或雷）。**注意：不要求"开局线索下解唯一"**（见 §2 口径说明）；但必须独立数出"开局相容方案数"，并核对文档是否**如实披露**了 >1 的关卡。
2. `rowRuns`/`colRuns`/`opening`/`mines` **互相一致**。
3. 阅读 `game/index.html`（或发布包 `dist/.../index.html`），确认其**实现了本文件 §1 的规则**（flood fill、命数、插旗、胜利条件、`showRuns` 控制线索显示），并在 DOM 桩里把**全部关卡**实际玩到 `status="won"`。
4. 发布包结构：ZIP 根目录含 `index.html` 与 `README.txt`、HTML 零外部引用。
5. 关卡面板提供 **「全部解锁」开关**（给评审/开发直接跳关）：默认关闭、状态写 `progress.devUnlock` 并持久化、不影响通关记录；关闭后恢复"通关上一关才解锁"。
6. **星座图鉴**（右上角「✦ 图鉴」）：按真实赤经/赤纬投影展示已通关星座；未通关的星座不得泄露星图内容（可显示为未点亮）；「全部点亮」只影响图鉴显示，不写入通关记录。
7. **意见箱**：确认**没有任何网络请求**；确认玩家输入**没有写入 `localStorage`**；「复制 / 导出 / 查看作者邮箱」三条路径在无网环境下均可用（邮箱弹窗只显示地址并提供复制，不自动发信）；确认没有把玩家输入偷偷发送出去。
7. 文档事实核对：`tools/report.md` 与两份交付文档里的关键数字与实际一致；发现"文档说 X、实测 Y"必须写明。
