## 1. 玩法定义

网格 N×N，每格是**雷**或**安全格**（初始全部未翻开）。
  
**目标：把所有格子分类完毕 —— 所有安全格已翻开，且所有雷已插旗。**

### 两种操作（**无模式切换，按设备区分**）

- 📱 触摸：**轻触 = 观测**（即时）；**长按（~380ms）= 标记**
- 💻 鼠标：**单击 = 观测**（即时）；**双击 = 标记**；**右键 = 立即标记**
- ⌨️ 键盘：Enter = 观测；空格 = 标记

| 操作             | 行为                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **观测**（点未翻开的格：手机轻触 / 电脑单击） | 若是**雷** → 扣 1 条命，该格变为"已翻开的雷"（等同已标出，不重复扣命）；若是**安全格** → 翻开并显示**邻域雷数**（周围 8 格的雷数量，0–8）；若该数为 **0** → 自动 flood fill 展开相连的 0 区，并翻开其边界上的数字格 |
| **标记**（手机长按 ~380ms / 电脑双击或右键） | 标记 / 取消标记为雷（不影响命数）。手机长按被消费掉后抬起不会再观测；手指划动超容差（12px）则取消                                                                                                                   |

### 线索

1. **邻域数字**：翻开的安全格上的数字（永久可见）—— 来自"扫雷"。
2. **行列连续块线索**（**由关卡数据的 `showRuns` 决定**；10 关初版中第 1–3 关不显示、第 4–10 关显示）：每行左侧、每列上方显示该行/列中**连续雷块的长度序列**——来自"数织"。
   - 例：`2 1` = 先 2 个连续雷、至少 1 个安全格、再 1 个雷。
   - 该行/列没有雷 → 显示 `0`。
3. **开局赠送**：每关给定一个已翻开的 **0 格**（`opening`），进入关卡即自动 flood fill，让玩家一开始就有信息。

### 胜负

- **胜利**：所有安全格已翻开 **且** 所有雷都已"标出"——*插旗* 或 *已被探爆（翻开的雷）* 都算标出。
  - 修订 v1.1（2026-10-21）：原措辞为"所有雷已插旗（严格全覆盖）"。独立复核指出实现里"踩爆但未插旗"的雷也计入胜利判定，与本文件字面冲突。经确认**实现的做法是正确的**：踩爆的格子已经翻开，界面不允许对其插旗，若胜利要求严格插旗，则"踩爆过的雷"会让该局**永久不可胜**。故此处修订为与实现一致，并明确"探爆 = 标出"。
- **失败**：命数归 0（默认 3 条命）。
- 状态栏显示：`已翻开 a/b · 已标雷 m/M`，**命数以 3 颗望远镜图形展示并依次熄灭**——`❤❤❤` → `❤❤♡` → `❤♡♡` → `♡♡♡`（命数归零即失败）；`m` 同样包含已探爆的雷。望远镜组必须有 `aria-label`（如「剩余命数 2 / 3」），不要逐颗朗读符号。
- 补充说明（v1.1）：**已插旗的格子会挡住 flood fill**（与经典扫雷一致）——数字为 0 的格连锁展开时，已插旗的格子不会被自动翻开，需要玩家自行取消插旗后再探。这不是缺陷，是这个玩法的既有惯例；实现与复核项以此为准。

## 2. 关卡数据格式（JSON，单一事实源）

```json
{
  "id": 1,
  "name": "第 1 关 · 学会看数字",
  "size": 6,
  "mines": [[r, c], [r, c]],
  "showRuns": false,
  "rowRuns": [[2], [], [1, 1]],
  "colRuns": [[1], [3]],
  "opening": [2, 2],
  "lives": 3,
  "teach": "点开的数字 = 它周围 8 格里有几颗雷。",
  "technique": "single-point"
}
```

| 字段          | 类型           | 说明                                                                      |
| ----------- | ------------ | ----------------------------------------------------------------------- |
| `id`        | int          | 1..N（N = 关卡总数）                                                          |
| `name`      | string       | 关卡标题（含教学语义）                                                             |
| `size`      | int          | 边长（10 关初版：6 → 7 → 8）                                                    |
| `mines`     | `[r,c][]`    | 雷的坐标（0-based）。**仅用于胜负判定**，界面不得直接展示                                      |
| `showRuns`  | bool         | 是否显示行列连续块线索（10 关初版：第 1–3 关 `false`，第 4–10 关 `true`；**以数据为准，不由关卡序号硬编码**） |
| `rowRuns`   | `number[][]` | 每行的连续雷块长度序列；`[]` 或 `[0]` 表示该行无雷（**统一用 `[]`**）                           |
| `colRuns`   | `number[][]` | 同上，每列                                                                   |
| `opening`   | `[r,c]`      | 已翻开的 0 格（**必须保证邻域雷数 = 0**）                                              |
| `lives`     | int          | 命数，默认 3                                                                 |
| `teach`     | string       | 进入关卡时显示的提示（可为空串）                                                        |
| `technique` | string       | 该关主要考察的推理技巧标签（用于迭代文档）                                                   |

**一致性要求（生成器必须自证）**：`rowRuns`/`colRuns` 必须与 `mines` 完全一致；`opening` 必须是安全格且邻域雷数 = 0；每关必须**零猜测可完成**——即模拟一个只做可靠推理、绝不猜的玩家，每一步都存在可证明安全（或可证明是雷）的格子，直到全盘判定完毕。

> **关于"唯一解"的口径（v1.2 修正）**：本文件原写作"每关必须唯一解"。独立复核指出这**不是**本作成立的判据，且与本作实际形态不符：
>
> - **零猜测可完成 ≠ 开局线索下解唯一**。扫雷类玩法靠**探格**不断获得新数字，玩家的收敛是路径依赖的；"开局那一眼的线索"本身完全可能有多个相容布雷方案。
> - 实测（T13 独立复核，10 关初版 v0.3）：**26 / 1 / 1 / 8 / 1 / 2 / 20 / 68 / 1 / 11**（按第 1–10 关顺序）；即第 **1、4、6、7、8、10** 关开局线索有歧义，其余为 1。**这些关卡全部仍然零猜测可完成**。
> - 因此契约要求是：**必须零猜测可完成**；开局相容方案数**必须如实披露**（>1 的关卡不得被描述成"唯一解"）。

## 3. 难度带与教学意图（10 关初版；50 关沿用同一分段逻辑）

难度轴：**是否需要第二套线索 → 棋盘尺寸 → 雷数与线索结构**。

| 关            | 尺寸        | 线索               | 教学意图                                                         |
| ------------ | --------- | ---------------- | ------------------------------------------------------------ |
| **1**（纯扫雷入门） | 6×6       | **只有邻域数字**       | 教会"翻开看数字"。必须**只靠邻域推理**就能零猜测通关（数织贡献 = 0）                      |
| **2**（引入数织）  | 6×6       | 邻域数字 **+ 行列连续块** | 立刻上融合：教会"行/列的连续块数字也在告诉你雷在哪"；**数织贡献要求 ≥5 格**（实测 12 格），保证不是贴标签 |
| **3–5**      | 6×6 → 7×7 | 两者都有             | 交叉推理；**只用邻域推理会推死、必须用数织线索**                                   |
| **6**（结构性线索） | 7×7       | 两者都有             | `0` 行/列（生成时强制包含至少一条空行或空列，保证该教学点真实存在）                         |
| **7–10**     | 8×8       | 两者都有             | 尺寸与密度收尾，长链推理                                                 |

> 教学文案（`teach`）**只在首次引入新机制时非空**（10 关初版：第 **1、2、6** 关非空），其余留白。

## 4. UI 验收标准（T7）

1. **单文件**：`game/index.html` 自包含、无外部依赖、**无任何网络请求**，`file://` 双击即玩。
2. **手机竖屏可用**：棋盘自适应宽度，无横向滚动；pointer/touch 与鼠标点击都支持。
3. **无模式切换**：手机「轻触观测 / 长按标记」、电脑「单击观测 / 双击或右键标记」。**操作提示放在棋盘正上方（紧跟「第 N/50 关」那行）并加粗突出**；长按不弹系统菜单（-webkit-touch-callout:none）。
4. **结算条按钮按结果区分**：**失败**时结算条只给「重来本关 / 换个关卡」，**不出现「结算」**（失败 modal 已经弹过，重复打开没有信息量）；**通关**时保留「结算」（用于回看星座揭晓）与「下一关」。
5. **同一时刻只出现一个「重来本关」**：游戏进行中显示常驻重玩按钮；一旦结算（通关/失败）出现，常驻按钮隐藏，只保留结算 modal / 结算条里的入口。
5. **首次进入第 1 关**弹一次玩法说明 modal（不超过三句话），关闭后写入本地 introSeen，之后不再弹；重置进度后也不再弹。
6. **状态栏**：已翻开 a/b · 已标记 ★ m/M · **3 架望远镜表示命数并依次熄灭**（见 §1）。
5. **教学文案**：进入关卡显示 `teach`；`teach` 为空串时**不显示教学条**（不出现空条）。
6. **通关用 modal 收尾**：胜利时弹出居中 modal（遮罩 + 卡片），标题如「第 N 关 · 通关！」，按钮 **「重来本关」** 与 **「下一关」**；**最后一关**标题改「全部通关！」且不出现点了没反应的死按钮（禁用或隐藏，判断基于 `LEVELS.length`）。键盘可达（Tab / Enter，Esc 行为自定但若可关闭则需有再次打开的入口），手机竖屏卡片自适应、按钮 ≥44px、遮罩阻挡棋盘误触。失败时**复用同一 modal**（标题如「踩到雷了」+「重来本关」），且不改变失败后的规则行为。
7. **关卡选择与进度**：支持任意关数（三态：已通关 / 当前 / 未解锁）与 `localStorage` 进度记忆（读写包 `try/catch`，不可用时静默降级为内存进度）。
8. **关卡数据内嵌**在这个注释块之间，便于 Lead 注入真实数据：
   ```
   /* LEVELS_INJECT_START */
   const LEVELS = [ /* 占位数据 */ ];
   /* LEVELS_INJECT_END */
   ```
9. 界面**不得展示 `mines`**。

## 5. 生成器交付标准（T6/T10，lead）

- `tools/generate_levels.py`：生成器 + **逻辑求解器**（同时使用"邻域计数传播"与"数织行/列枚举"两种推理），**曲线驱动批量生成**（初版 10 关，目标 50 关）。
- 校验必须自证：**零猜测可完成**、线索与 `mines` 一致、`opening` 为 0 格且开局展开 ≥5 格、教学带意图符合（教学带必须"仅邻域推理可通关"）。
- 开局相容方案数：不含连续块线索的关卡用**精确枚举**给出确切数字；含连续块线索的组合空间过大时**如实标注"未判定"**，由独立复核补测。
- 产出 `tools/levels.json`（**将注入 HTML 的同一份数据**）与 `tools/report.md`（每关的推理序列、步数、接受/拒绝统计、相容方案数 → 迭代文档素材）。
- 发布打包：`tools/build_release.py` 产出 `dist/<姓名>-游戏本体/index.html` 与 `<姓名>-游戏本体.zip`（**ZIP 根目录即 `index.html`**，符合提交平台要求；ZIP 内另附 `README.txt`，内容取自 `tools/README_source.txt`，说明玩法/操作/离线运行），并写出 `dist/build_manifest.json`（含各输入/输出的 sha256）。

## 6. 独立复核标准（T8/T11）

复核者必须**独立实现**校验（不得复用 lead 的求解器代码），确认：

1. **每关零猜测可完成**（模拟玩家：每一步始终存在可证明的安全格或雷）。**注意：不要求"开局线索下解唯一"**（见 §2 口径说明）；但必须独立数出"开局相容方案数"，并核对文档是否**如实披露**了 >1 的关卡。
2. `rowRuns`/`colRuns`/`opening`/`mines` **互相一致**。
3. 阅读 `game/index.html`（或发布包 `dist/.../index.html`），确认其**实现了本文件 §1 的规则**（flood fill、命数、插旗、胜利条件、`showRuns` 控制线索显示），并在 DOM 桩里把**全部关卡**实际玩到 `status="won"`。
4. 发布包结构：ZIP 根目录含 `index.html` 与 `README.txt`、HTML 零外部引用。
5. 关卡面板提供 **「全部解锁」开关**（给评审/开发直接跳关）：默认关闭、状态写 `progress.devUnlock` 并持久化、不影响通关记录；关闭后恢复"通关上一关才解锁"。
6. **星座图鉴**（右上角「✦ 图鉴」）：按真实赤经/赤纬投影展示已通关星座；未通关的星座不得泄露星图内容（可显示为未点亮）；「全部点亮」只影响图鉴显示，不写入通关记录。
7. 文档事实核对：`tools/report.md` 与两份交付文档里的关键数字与实际一致；发现"文档说 X、实测 Y"必须写明。
