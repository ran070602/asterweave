## 5. 已知坑（都踩过，改前先看）

1. SVG 上 `setPointerCapture` 会让 `click.target` 变成 SVG 根节点 → 选中逻辑要用 **pointerup 时记录的节点**。
2. 手势标志（`skyMoved` 之类）必须在手势结束时**复位**，否则"拖动一次后再也点不开"。
3. **大段替换 JS 函数区间风险高**：曾误删相邻的 `skyHintText()`，导致图鉴一打开就抛错、地图整片空白 → 改完必须跑构建 + 无头验证。
4. 无头浏览器里 CSS 过渡后的 computed 值不可信（见上）。
5. 文档同步脚本曾用固定正则匹配表格首尾 → **重复插入**；已改为"最长表格块、逐行比对、幂等"。
6. GitHub `push` 偶发 `502 / remote end hung up`，重试即可；Pages 部署 1–3 分钟生效。
7. `tools/levels.json` 属另一会话：本会话若要动它（如改 `teach`），需同时同步生成器，并在此记录。

## 11. 无尽记分重做 + 望远镜语义修正（v9）

玩家实测反馈："第一把什么都不干也是 198 分，翻出正确牌子还要扣分，翻到错误的变成 0 分"。**根因是我的公式设计错了，不是算错**：

- 原公式 `分数 = 累计 + 剩余望远镜×200 − 总秒数×2` 是**实时推导值**，于是：开局 `0+1×200−0` = **200 起跳**（过 1 秒变 198）；**每秒 −2 的时间惩罚**让分数边玩边掉（玩家感知为"翻对牌反而扣分"）；失误让望远镜 1→0，**200 的望远镜奖励整块消失** → 取下限变成 0。

**已改为符合直觉的记分**：

- **开局 0 分**；**进行中的分数只增不减**（`runScore()` 直接返回累计值）。
- 只有**通关**加分：`100 + max(0, n−5)×10（难度）+ 25×min(连击,20)`（连击越高越多）。
- **失误不掉分**，代价是「少一架望远镜 + 连击清零」，并弹提示。
- **时间不扣分**，只作为统计（本轮用时 / 最快一题）。
- **结算总分** `runFinalScore() = 通关得分 + 剩余望远镜×200`，结束页**列出明细**：「通关得分 X ＋ 望远镜奖励 Y（N 架 × 200）」。

**⚠️ 本条结论已于 v12 被用户推翻**（用户实测：「1 架望远镜却能失误两次」是 bug）。现行为**掉到 0 即结束**，即开局 1 架 = 只能失误 1 次。以下为历史记录：

**同时修正一处偏离约定的实现**：原代码在望远镜**掉到 0 的那一刻**就结束本轮，而约定是「**0 架时再失误**才结束」（即开局 1 架 = 能承受 1 次失误）。现已按约定改为：掉到 0 架仍可继续（此时一击必死，提示语改为"望远镜已用尽 · 再失误就结束"），并可靠通关补回望远镜（每 3 题 +1，0 架也能补）。

实测：`开局=0 → 干等3秒=0 → 过1题=145 → 过2题=335 → 失误1=335 → 失误2=335`，**单调不减=true**，结算总分 335（明细：通关得分 335 ＋ 望远镜奖励 0）；望远镜语义 `1 架/playing → 0 架/playing → 0 架时再失误/lost`；全部测试 `err=` 空。

- **v12 两处修复（用户反馈）**：
  1. **无尽模式失误次数**（用户报的 bug，已核实存在）：`ENDLESS_START_LIVES = 1`，但 `endlessMistake()` 写的是"**0 架时再失误才结束**"，于是 1 架望远镜实际能失误 **2 次**。改为 **望远镜数 = 可失误次数**：`run.lives -= 1` 后若 `<= 0` 立即 `endEndlessRun('mistake')`（1 架 → 只能失误 1 次；后续补给到 N 架则容忍 N 次）。
     顺带修掉一个残留显示问题：致命失误时 `endEndlessRun()` 内部先 `render()`（此时 `S.lives` 仍是旧值 1），而外层 `if (!over)` 又不再重绘 → 望远镜停在 `1/3`。改为结束后也无条件 `render()`。
     实测：无尽模式从 `命数 1 / 3` 开始，按到第 3 格踩到雷 → 弹窗立刻变「本轮结束」；按完全部 36 格后 `命中雷数 = 1`、`望远镜显示 = 剩余命数 0 / 3`；零 JS 报错。
  2. **重玩不限时**（用户要求）：`timeIsTimed()` 增加 `!isCleared(S.index)`——重玩已通关的关卡不再倒计时、不再判负、不再记最快用时；首次挑战才限时。实测：重玩第 11 关芯片隐藏、信息行无「限时」、操作后仍隐藏；首次挑战第 12 关显示 `限时 3:00`。
  - 测试踩的坑（记下来）：`render()` 会重建盘面 innerHTML，**缓存的 `.cell` NodeList 会变成已分离节点**，循环里必须每次重新 `querySelector`；另外 `.overlay` 有 160ms 过渡，同步读 `visibility` 必然还是 `hidden`，判断弹窗要用 class（`show`）而不是 computed visibility。
